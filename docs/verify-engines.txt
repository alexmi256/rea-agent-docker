# job count), and npm `latest` and the GitHub releases agree. The pins were
# re-derived from the new release rather than assumed.
#
# Two admissions moved, and both were hard gates rather than preferences:
#
# - Ghidra 12.1.4 -> 12.2. REA 6.10's SUPPORTED_GHIDRA_VERSION is "12.2" and its
#   ADMITTED_GHIDRA_MINOR_FLOOR refuses anything below it, so the previous pin
#   would have been `unsupported` (not merely `compatible`) on the 6.9.0 line.
#   GHIDRA_VERSION and GHIDRA_ZIP moved together (ghidra_12.2_PUBLIC_20261016.zip).
# - JDK 21 -> 25. SUPPORTED_GHIDRA_JAVA_MAJOR is now 25; the image installs
#   openjdk-25-jdk-headless (25.0.5.1, now in noble) and every literal JAVA_HOME
#   mirror moved with it: Dockerfile ENV, Dockerfile engine.env, docker-compose.yml,
#   compose.http.yml, .env.example and the gitignored .env.
#
# Nothing else pinned needed a move. NODE_VERSION stays 24.22.3 (engines.node is
# unchanged: ^22.23.4 || ^24.22.1 || >=26.12.1), Hopper is still the vendor feed's
# 6.6.2 demo (launcher 226800f1...), and unblob 26.6.4, binwalk 3.1.0, WABT
# 1.0.42, pwntools 4.15.0, jadx-headless-mcp 0.7.1, apktool 2.12.1 and Wakaru
# 1.14.0 (digest 664fa067...) are all still what the release admits.
#
# 6.10 is a large breaking release (evidence_format 2, subject identities, MCP
# schema-profile removal, `rea mcp` in place of `rea <command> --mcp`, IDA
# `protocol: "native"`). None of it required an image change beyond the two
# admissions: the harness asserts results (`evidence_id`, decompiled text) rather
# than the removed fields, the image already invoked `rea mcp`, it already set
# REA_MCP_INPUT_SCHEMA_PROFILE=compact (never `full`), and its IDA registration
# template already used `"protocol": "native"`.
#
# Every count is identical to the 6.9.0 and 6.8.0 rounds on all four images
# (121/109/102/94 passed): 6.10.0 adds capability inside REA (UEFI/AMI NVRAM, Android
# boot/OTA, ELF dependency and DWARF readers, Maven/Gradle/NuGet metadata, SBOM
# export) and moves the engine, but adds no helper tool this image must supply and
# no check this harness already asserts. What did move is the catalog: 255 -> 263
# MCP tools (bundled skill v62 -> v63).
#
# NOTE: the `platform:` line in each run is redacted to 'Linux x86_64' - the
